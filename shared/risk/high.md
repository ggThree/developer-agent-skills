# High 风险

## 风险名称

核心路径失败、重要数据或安全边界受损。

## 风险等级

`High`（高风险，默认阻断合并或发布）。

## 判断依据

满足以下条件之一，并有明确触发路径时，判定为 High：

- 常见用户路径会崩溃、无法完成登录、支付、下单、保存或关键业务流程；
- 可能造成重要数据错误、丢失、重复处理，但影响范围有限或存在可验证恢复方式；
- 存在对象级越权、敏感日志、弱证书策略或凭证处理缺陷，但尚未达到大范围失控；
- API、数据库、配置、签名或依赖变化会破坏在用客户端或生产部署；
- 并发、事务、幂等或缓存缺陷可在正常负载下触发明显错误；
- Git merge/rebase/reset 可能重写已共享提交、混入未审查内容或使当前工作难以恢复；
- 发布门禁、关键测试或必要真机/集成验证明确失败。

高风险必须描述具体输入、状态或环境。只有“可能崩溃”而没有调用链、类型约束或复现方式的结论应标为证据不足。

## 影响范围

- 一个或多个关键业务模块、特定用户群、平台或生产环境；
- 订单、账号、权限、缓存、数据库记录和对外 API；
- 发布成功率、可用性、客服与运维响应；
- 通常需要模块负责人和测试确认，涉及生产或安全时需要运维/安全参与。

## 建议操作

1. 暂停合并或发布，保留最小复现证据。
2. 优先修复根因；若临时隔离，明确 feature flag、流量范围和失效时间。
3. 对正常、失败、重复、并发、旧版本和恢复路径进行定向测试。
4. 检查调用方与持久化副作用，不只修复表面 UI 或异常捕获。
5. 由责任人确认残余风险、监控指标和停止条件后才能继续。

## 回滚建议

- 选择可审计方式：共享 Commit 使用 `git revert`，未共享本地 Commit 可在确认后使用 `reset --soft` 或 `reset --mixed`。
- 回滚应用前核对数据库、配置、缓存和外部服务是否保持向后兼容。
- 保存目标 Diff、Commit SHA、制品版本和必要日志，保证能够重现与恢复。
- 回滚后执行核心路径回归，核对数据、错误率和依赖健康；不能仅以部署命令成功作为完成证据。

## 典型示例

| 场景 | High 成立证据 |
| --- | --- |
| 登录按钮永久禁用 | 请求 reject 路径没有恢复 loading，常见网络错误可触发 |
| 支付上下文错配 | AppID、openid、merchant 或 callback 来自不同应用上下文 |
| 事务未生效 | Spring self-invocation 绕过代理，部分写入在异常后保留 |
| iOS 信任绕过 | 正式构建无条件接受 server trust |
| 共享分支 rebase | 待重写 Commit 已推送且存在其他协作者 |

## 降级条件

当触发概率被可靠限制、核心路径不受影响、恢复方式经过验证且已有监控时，可降为 [`medium.md`](medium.md)。仅增加说明文档不能自动降低等级。
