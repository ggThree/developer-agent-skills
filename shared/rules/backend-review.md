# 后端代码审查规则

本规则面向 Spring Boot、Java/Kotlin 服务及常见 Node 服务端。Spring 项目先加载 [`../adapters/spring.md`](../adapters/spring.md)，Node 项目加载 [`../adapters/node.md`](../adapters/node.md)，再应用 [`review-rule.md`](review-rule.md)。

## 1. 请求入口与契约

- 从 Route/Controller 追踪到 Service、Repository/Mapper、Model 和外部服务。
- 核对 HTTP method、path、content type、认证、权限、限流和幂等要求。
- 请求校验覆盖必填、长度、范围、格式、枚举、跨字段约束和未知字段策略。
- 响应状态码、错误码、字段名、类型、空值、分页和日期格式与调用方一致。
- 不能把 Java 类型安全等同于外部输入已验证，也不能把前端校验当作服务端边界。

## 2. 认证、授权与租户隔离

- 区分“已登录”和“有权访问该资源”；每个对象级操作检查资源归属。
- 管理接口、批量接口、导出与内部回调具有独立权限边界。
- 多租户查询和缓存键必须包含租户维度，防止跨租户读取或覆盖。
- token、session、签名、nonce、时间窗和重放防护符合协议。
- 日志和异常不得暴露凭证、个人信息、SQL、内部拓扑或签名材料。

## 3. 事务与数据一致性

- 事务边界覆盖必须原子完成的写操作，避免 self-invocation 使 Spring 事务失效。
- 检查异常是否被吞掉导致事务不回滚，以及 checked exception 的回滚策略。
- 唯一约束、乐观锁、行锁、隔离级别和重试组合能够处理并发。
- 外部调用与数据库事务的顺序有补偿或 Outbox 等一致性设计。
- 数据迁移具有兼容窗口、批量大小、索引策略、回滚或向前修复方案。

## 4. 查询与持久化

- SQL/MyBatis/JPA 参数必须绑定，动态排序和表名使用白名单。
- 防止 N+1、无界查询、全表扫描、大 offset、错误 join 和重复行。
- 更新与删除必须有精确条件；批量操作报告影响行数并设置上限。
- 时间、金额与计数使用正确精度和时区；序列化与数据库类型一致。
- 缓存 key、TTL、失效顺序与数据库提交保持一致，处理缓存穿透和击穿。

## 5. 错误、重试与幂等

- 区分客户端错误、业务冲突、依赖失败和服务端缺陷，映射稳定错误码。
- 重试只用于可重试错误，设置次数、退避、超时与总预算。
- 支付、订单、消息消费和回调以业务唯一键实现幂等，不能仅依靠进程内锁。
- 消息 ack、死信、顺序和重复投递路径有明确处理。
- fallback 不得把失败伪装成成功或返回不可区分的空数据。

## 6. 配置与运行时

- 配置来源、profile、默认值和环境变量命名明确；生产敏感配置不入库。
- 线程池、连接池、队列、文件句柄和请求体大小有边界。
- 健康检查区分存活与就绪，不能因可选依赖让实例永久摘除。
- 日志包含可追踪 ID 和必要上下文，但不记录敏感 payload。
- 关闭流程停止接流量、等待在途任务并释放资源。

## 7. API 兼容性

- 删除或重命名字段、改变类型/语义、收紧校验和修改默认值都可能破坏旧客户端。
- 新字段优先保持向后兼容；版本协商和灰度期间同时考虑新旧调用方。
- 事件 Schema 与同步 API 一样需要版本和兼容策略。
- 文档、OpenAPI、DTO、数据库和前端调用必须检查为同一契约。

## 8. 最小验证

1. 编译或目标模块测试；
2. Controller/Service/Repository 的受影响测试；
3. 正常、无权限、非法输入、重复请求、并发与依赖超时路径；
4. 数据库 migration dry-run 或隔离环境验证；
5. 与真实调用方核对 request/response；
6. 性能敏感查询使用执行计划和受控数据量验证。

## 9. 高风险信号

数据库 Schema、生产配置、认证授权、支付记账、批量写入、事务边界、消息消费语义、对外 API 破坏性变化和依赖大版本升级，至少按 [`../risk/high.md`](../risk/high.md) 处理；可能导致不可恢复数据破坏或大范围越权时升级为 [`../risk/critical.md`](../risk/critical.md)。
