# 发布准入规则

本规则用于回答“当前版本是否允许发布”。结论必须基于可追溯证据，不能因为构建成功或工作区干净就自动判定可发布。

## 1. 准入结论

只能输出以下三种结论：

- **允许发布**：所有阻断项通过，残余风险已被明确接受，回滚路径可执行。
- **有条件允许**：不存在 Critical/High 未解决风险，但仍需在规定窗口完成明确的人工验证或观察。
- **禁止发布**：任一阻断项失败、证据不足以排除高风险，或关键责任人未确认。

## 2. Git 与版本基线

- 工作区和暂存区无意外修改，未跟踪文件已解释；
- 当前分支、upstream、ahead/behind 与目标发布分支一致；
- 远端引用在本轮更新，或明确标注未更新的限制；
- 发布范围的 Commit 可追溯且经过审查；
- Tag 不与现有 Tag 冲突，指向计划发布的准确 Commit；
- 版本号遵循 [`../references/semantic-version.md`](../references/semantic-version.md)，应用内版本、构建号与发布元数据一致。

发布过程中涉及 push、merge、rebase 或 reset，继续遵循 [`git.md`](git.md) 的独立确认规则。

## 3. 源码与调试残留

在目标 Diff 和发布源代码范围内检查：

- 未完成任务标记、临时分支和仅用于诊断的断言；
- `FIXME` 及同类已知缺陷标记；
- `print`、`NSLog`、`console.log`、调试开关和测试入口；
- mock 地址、绕过认证、测试账号、固定验证码和宽松证书校验；
- 敏感信息、生产数据样本、私钥、token 与证书文件。

命中不等于自动失败：必须逐项判断是否为生产合法用途。但认证绕过、敏感信息和证书信任绕过属于阻断项。

## 4. 依赖与构建配置

- iOS 核对 `Podfile`、`Podfile.lock`、`Package.swift`、`Package.resolved` 与 `project.pbxproj`；
- Node 核对 `package.json` 与实际采用的单一 lockfile，防止多个包管理器解析结果冲突；
- 后端核对 Maven/Gradle lock、容器基础镜像和运行时版本；
- 依赖升级说明来源、版本跨度、安全影响和回滚方式；
- Build Configuration、环境变量、feature flag、签名与产物渠道匹配目标环境。

依赖、签名和生产配置变化不能作为普通维护项静默带入发布。

## 5. 质量门禁

- 项目规定的 lint、typecheck、单元测试、集成测试与构建实际通过；
- 关键业务路径完成人工回归，包含失败与恢复路径；
- 新功能和修复有与行为对应的测试，或明确说明无法自动化的原因；
- 没有未解释的编译 warning、测试跳过或 flaky 结果；
- 安全、性能和可访问性检查按变化范围执行。

只运行局部命令时，结论必须限定到该模块，不能推断全仓库通过。

## 6. 平台与业务专项

- iOS：目标 scheme/archive、签名、Entitlements、隐私声明、最低系统版本与真机能力；
- Web/uni-app：生产构建、浏览器/多端矩阵、source map、缓存与 CDN 失效；
- 后端：数据库迁移、配置、容量、健康检查、灰度、依赖服务与数据兼容；
- 支付/认证：AppID、用户标识、商户/密钥、回调环境、幂等和服务端最终状态。

技术栈检查分别参照 [`ios-review.md`](ios-review.md)、[`frontend-review.md`](frontend-review.md) 与 [`backend-review.md`](backend-review.md)。

## 7. 发布、观察与停止条件

发布计划必须包含：

- 负责人、时间窗、顺序和灰度比例；
- 发布前备份或恢复点；
- 核心技术指标与业务指标的基线；
- 明确的停止条件，例如错误率、崩溃率、延迟或数据差异超过阈值；
- 观察时长和决策人；
- 可执行回滚步骤与回滚后验证。

涉及不可逆数据迁移时，优先设计兼容发布和向前修复；单纯回滚二进制不构成完整方案。

## 8. 风险门禁

- 未缓解的 [`Critical`](../risk/critical.md) 或 [`High`](../risk/high.md) 风险：禁止发布；
- [`Medium`](../risk/medium.md) 风险：需要负责人、规避措施、观察指标和处理时限；
- [`Low`](../risk/low.md) 风险：可记录进入后续维护，但不能隐瞒。

## 9. 输出要求

使用 [`../templates/release_note.md`](../templates/release_note.md) 记录版本变化，并在结论中逐项列出：已通过门禁、失败门禁、未执行验证、残余风险、发布步骤、停止条件和回滚步骤。
