# Release Note 模板

Release Note 面向使用者与维护者，内容必须来自本次发布范围内的 Commit、PR、版本差异和已验证结果。内部实现细节只有在影响兼容、部署或回滚时才进入发布说明。

## 固定结构

### 版本概览

写明版本号、目标分支、Tag、发布日期和发布目的。版本规则遵循 [`../references/semantic-version.md`](../references/semantic-version.md)。

### 用户可感知变化

按以下类别归纳，无内容的类别省略：

- 新增功能；
- 问题修复；
- 性能与稳定性；
- 交互与可访问性；
- 文档与运维。

每一项说明“变化 + 对用户的意义”，不复制 Commit 列表。

### 兼容性与升级说明

明确列出 API、数据库、配置、依赖、最低系统版本、权限、证书与缓存的变化。破坏性变化必须包含调用方改造方法与生效时点。

### 验证证据

列出实际执行的构建、测试、静态检查与手工回归，包含命令或测试范围和结果。未执行的项目放入“发布限制”，不得混入成功清单。

### 发布限制与已知风险

使用 [`risk_report.md`](risk_report.md) 的等级和字段，说明触发条件、影响与规避方式。不能使用模糊的“可能有问题”。

### 发布与回滚

记录发布顺序、观察指标、停止条件、回滚目标和回滚后验证。涉及数据迁移时必须说明向前修复策略，不能仅写“回滚代码”。

## 完整示例

```text
## 2.4.1 - 2026-08-02

目标分支：main
Tag：v2.4.1

### 问题修复

- 修复验证码接口失败后发送按钮无法再次点击的问题，弱网恢复后无需刷新页面。

### 验证证据

- `pnpm test --filter auth`：通过，18 个用例。
- Chrome 与微信开发者工具手工验证成功、超时、500 三条路径。

### 发布限制与已知风险

- iOS 真机网络切换未覆盖；发布后观察验证码失败率与重复请求率 30 分钟。

### 回滚

- 应用回滚至 v2.4.0；该版本不包含数据迁移。
- 回滚后验证登录成功率、验证码接口错误率和按钮恢复行为。
```

发布准入条件见 [`../rules/release-rule.md`](../rules/release-rule.md)。
