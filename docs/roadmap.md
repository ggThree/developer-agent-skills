# Roadmap

路线图按安全收益和可验证性排序。每个阶段只有在文档、示例、自动化验证、兼容说明和回滚策略同时完成后才发布。

## 0.1：Git 安全基线

状态：实现与本地质量门禁已完成，当前为发布候选；稳定 Tag 与 GitHub Release 尚未创建。

- 六个 Git Skills；
- macOS/Linux 非侵入式检查器；
- 四级风险模型与跨栈审查 Adapter；
- 安装、使用、架构、FAQ 和最佳实践；
- GitHub CI 与贡献治理。

## 0.2：托管平台协作

目标：在不自动改变远端状态的前提下，统一 GitHub、GitLab、Gitea 的 Pull/Merge Request 证据模型。

验收边界：

- 远端权限保持最小化，默认不执行远端写操作；
- PR 评论、合并、Tag 和 Release 仍需明确授权；
- 同一 Diff 在本地与远端分析结果可追踪；
- Token 永不写入报告、日志或示例。

## 0.3：策略与组织治理

目标：让团队在仓库内声明允许的分支策略、提交规范、发布门禁和风险阈值。

验收边界：

- 策略文件具备可验证 schema；
- 仓库策略不能削弱全局禁止项；
- 规则冲突给出来源和优先级；
- 策略迁移支持 dry-run 和差异报告。

## 0.4：MCP 适配

目标：通过 MCP 获取 PR、CI、Issue、制品与发布状态，为本地分析补充远端证据。

验收边界：

- MCP Adapter 与核心 Skill 解耦；
- 无 MCP 时全部本地能力仍可使用；
- 写操作工具默认不暴露或需要宿主级审批；
- 外部响应经过字段校验、限流和秘密脱敏。

## 1.0：稳定契约

目标：冻结 Skill 输入输出契约、脚本退出码和风险等级语义，为第三方 Adapter 提供稳定扩展面。

发布条件：

- 至少覆盖三类真实开源仓库规模；
- macOS 与两个主流 Linux 环境持续通过；
- 各 Skill 具备正向、阻断和边界场景；
- 安全审查没有未处理的 Critical/High 问题；
- 升级指南覆盖所有不兼容变化。

## 不纳入核心的能力

- 自动强制推送、自动 hard reset、自动删除分支；
- 绕过分支保护、CI 或代码所有者审批；
- 存储或分发托管平台长期凭据；
- 用模型主观结论替代构建、测试和运行证据。
